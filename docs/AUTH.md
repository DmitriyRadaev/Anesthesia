# Авторизация, роли, права

## Механизм

1. `POST /api/auth/login/` `{"username", "password"}` → `{"token", "expires_at", "user"}`.
   * 401 — неверный логин/пароль; 403 — учётная запись деактивирована; 429 — превышен лимит попыток.
2. Все остальные запросы: заголовок `Authorization: Bearer <token>`.
3. `POST /api/auth/logout/` — отзыв текущего токена (204). `GET /api/auth/me/` — текущий пользователь.
4. `POST /api/auth/change-password/` `{"old_password", "password"}` — смена своего пароля; прочие сеансы завершаются.

Выбран токен, а не сессия с cookie: SPA и интеграции (СППВР, шлюз мониторов) используют один механизм, нет
CSRF-зависимости, поддерживается несколько одновременных сеансов. Токен хранится во `sessionStorage` браузера
(закрытие вкладки = выход), на сервере — только SHA-256 хеш; срок жизни задаёт `AUTH_TOKEN_TTL_HOURS` (по умолчанию 12 ч).
Любой ответ 401 во frontend завершает сеанс и возвращает на страницу входа.

## Роли

| id | Роль | Назначение |
|----|------|-----------|
| 1 | Врач | Клиническая работа; ОС — только со своим участием |
| 2 | Медсестра/Медбрат | Заполнение протокола и наркозной карты; карточки пациентов и ОС — просмотр |
| 3 | Администратор | Управление пользователями, отчёты; **без доступа к медицинским данным** |
| 4 | Заведующий отделением | Полные клинические права, управление пользователями, отчёты |
| 5 | ИО заведующего | Как заведующий, но не может назначать роли руководителей/администратора и изменять их учётные записи |

## Матрица прав

| Действие | Врач | Медсестра | Админ | Заведующий | ИО |
|----------|:----:|:---------:|:-----:|:----------:|:--:|
| Справочники, свой профиль, смена пароля | ✓ | ✓ | ✓ | ✓ | ✓ |
| Реестр/карточки пациентов: просмотр | ✓ | ✓ | — | ✓ | ✓ |
| Пациенты: создание, изменение, архив | ✓ | — | — | ✓ | ✓ |
| Пациенты: удаление (без ОС) | — | — | — | ✓ | ✓ |
| ОС: просмотр | ✓ | ✓ | — | ✓ | ✓ |
| ОС: создание/изменение | ✓¹ | — | — | ✓ | ✓ |
| ОС: отмена/завершение | ✓² | — | — | ✓ | ✓ |
| Протокол, наркозная карта, лаборатория, показатели: просмотр и изменение | ✓ | ✓ | — | ✓ | ✓ |
| Медицинский персонал (списки врачей/медсестёр) | ✓ | ✓ | — | ✓ | ✓ |
| Пользователи: список, создание, роль, активация, пароль | — | — | ✓ | ✓ | ✓³ |
| Отчёт 41.10 | — | — | ✓ | ✓ | ✓ |
| Приём HL7 по HTTP | — | — | — | ✓ | ✓ |
| СППВР (`/api/cdss/...`) | ✓ | ✓ | — | ✓ | ✓ |

¹ только назначая врачом себя или без врача. ² только если назначен врачом этого ОС.
³ без назначения ролей «Администратор»/«Заведующий»/«ИО» и без изменения учётных записей с этими ролями.

Дополнительно: нельзя изменить собственную роль и деактивировать себя (защита от потери доступа);
учётную запись суперпользователя меняет только суперпользователь. Удаление пользователей не предусмотрено
(сохраняется история участия в ОС) — используется деактивация, которая немедленно завершает все сеансы.

Интеграции (СППВР, `POST /api/monitoring/hl7/`) дополнительно принимают заголовок `X-API-Key`, равный
`INTEGRATION_API_KEY` (если переменная не задана — доступ только по токену).

## Отличия от исходной системы

* Удалена авторизация через МИС БАРС (`/api/login` с проверкой в БАРС, `PUT /session_bars_prolongation`,
  хранение `bars_token`, `user_bars_id`, поиск сотрудников в БАРС).
* В исходной политике врач/медсестра могли изменить **свою роль** через `PATCH /users/{id}` — исправлено.
* Блоки протокола/карты в исходной системе были доступны любому авторизованному пользователю — теперь только клиническим ролям.

## Инициализация

* Первый администратор: `python manage.py create_admin` (интерактивно) или переменные
  `DJANGO_ADMIN_USERNAME`/`DJANGO_ADMIN_PASSWORD` при старте контейнера (`create_admin --if-missing`).
* Заранее подготовленные пользователи: `python manage.py load_users users.json` (см. `backend/data/users.example.json`).
  Файл с реальными данными не хранится в репозитории; без пароля в файле генерируется случайный и выводится однократно.
